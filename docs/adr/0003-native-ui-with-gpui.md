# Native desktop UI with GPUI

Roastro's screens are a native desktop app written in Rust with GPUI and gpui-component (through `gpui-kit`, pinned to an exact version), not a web UI. The UI runs in the same process as the engine and talks to it through the same request queue and broadcast that the HTTP API uses, without serialization. The HTTP API and live WebSocket stay, but they are no longer how the main UI works: they are kept for later read-only viewing from another device (M8). A spike on 2026-11-16 (branch `spike/gpui`, issue #20) showed the risky parts work: a live roast chart drawn on GPUI's primitives from the real recorder, buttons and text input under headless UI tests, and a release build plus smoke run on Windows in CI. It was chosen over the planned web UI because the web would not be used in the product and building both doubles the work; it keeps the whole product in one language. The costs accepted: GPUI is pre-1.0 and its distributions churn (exact pins, a committed lockfile, occasional upgrade work), the roast chart is custom drawing rather than a chart library, the React prototype is only a visual reference, and Windows builds come from CI rather than a local cross-compile.
