# Write Roastro in Rust

Roastro is written in Rust. The existing Go code (simulator, probe, terminal monitor and the `regmap`, `plc`, `roast` packages) is rewritten module by module and removed once its Rust counterpart passes the same tests; until then the Go tools keep running, so there is always a simulator to develop against. The workload does not need Rust (one PLC read per second, SQLite, a local web UI), and Go was already working; the choice is about the product's long-term direction and the team's chosen language. What it buys: sum types and exhaustive matching for roast states and event kinds, data races ruled out at compile time, and a path to a desktop shell (Tauri) and to sharing code with the web UI through WebAssembly. What it costs: the M0 tools are rebuilt before M2 ships, and cross-compiling to Windows with SQLite (C code via `rusqlite`) needs more setup than Go's pure-Go driver did. The rule against copying Artisan's GPLv3 code is unchanged.
